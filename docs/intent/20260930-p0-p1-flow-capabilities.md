## Background

Pomelo PW 已提供导航、交互、等待、条件、循环和 evaluate，但动态数据仍缺少完整的生产、引用和消费机制。相邻 K12 项目的 `.pomelo-pw/material-parse-all.yaml` 共 259 行，其中 4 个脚本块占 206 行；脚本承担分页采集、状态保存、业务判断、逐条提交、任务轮询和汇总。

拆分任务时，变量引用主要用于字符串替换，evaluate 返回值无法绑定为后续变量，foreach 只是 loop 的别名。条件、等待及执行结果也不足以支持上述流程直接组合。这些通用能力是本系列的目标，教材和 MinerU 的具体业务规则仍由调用方表达。T01 已解决结果绑定和类型化引用，后续能力按任务顺序推进。

## Goals

- 覆盖已讨论的全部 P0/P1 方向：运行时上下文、集合遍历与数据条件、条件等待与轮询、HTTP 请求、DOM 数据提取、断言与结构化结果。
- 将能力拆成可单独审查、实施、验收的任务，明确依赖和工作量。
- 让复杂流程通过步骤结果传递数据，通过控制步骤表达顺序与等待，减少手写通用 JS。
- 使用统一的新 YAML、数据和结果契约，不实现旧接口兼容适配；受影响的仓库示例、测试和说明随相关任务迁移。

## Non-goals

- 不纳入 P2/P3 的外部脚本、子流程、专用分页封装、检查点恢复和并发调度。
- 不为教材或 MinerU 增加专属步骤，不接管业务任务队列。
- 不以消灭所有 JS 或达到指定 YAML 行数作为目标；特殊页面逻辑和少量转换可继续使用 evaluate。
- 除用户本轮明确指定的材料脚本 v4 改写外，不修改相邻 K12 仓库；不执行真实批量解析，不启动或调整其开发服务器。
- 系列入口负责意图与任务边界；各任务按阶段单独推进，未获阶段授权前不写产品代码或 Verification 文档。

## User scenarios

- 页面或接口返回记录集合，后续步骤直接遍历集合并引用每条记录的字段。
- 点击提交后读取任务 ID，定期刷新任务数据，直到出现明确终态，再记录处理结果。
- 翻页后等待页面数据满足条件，提取各行字段，检查总数、唯一性或业务状态。
- 用户和 Agent 从结构化输出中区分步骤失败、业务失败、跳过和成功。

## Suggested sequence

1. T01 建立数据契约，先解决成功结果绑定、类型化引用、作用域和结构化脚本参数。
2. T02 明确条件契约；随后推进 T03、T04、T05，形成完整的 P0 控制能力。
3. T06、T07 在 T01 稳定后即可独立排期，推荐先请求、再提取；T08 在控制语义稳定后接入断言和统一输出。
4. T09 用受控的分页列表与异步任务场景串联全部能力，验证任务拆分没有留下需要通用 JS 补齐的缺口。

第一批可用能力以 T01-T05 为界；完整 P0/P1 交付以 T09 为界。单个新增步骤完成不能代替系列验收。

## Acceptance

- 每个 P0/P1 方向至少对应一个独立任务，任务具备范围、场景、验收标准、依赖和工作量。
- 通过步骤结果传递对象和集合，不要求业务 flow 使用 sessionStorage 维持循环状态。
- 集合遍历、页面就绪等待、任务轮询均由通用步骤负责，轮询有明确超时和失败语义。
- 复杂示例能读取分页数据、顺序处理记录、等待任务终态并输出可核对的汇总。
- 仓库示例、测试和 Agent 说明统一使用新契约，基本交互和浏览器状态复用能力纳入正确性回归；不以维持旧接口为验收目标。
- 各任务覆盖对应步骤在顶层、分支和循环中的行为，嵌套参数在执行到该步骤时解析，校验能定位嵌套步骤。
- 只读查询的轮询、网络重试与已提交任务的业务失败分别处理，避免隐式重放已经成功的写操作。

## Decisions

- 所有任务采用用户指定的标准模式，不因任务较小改用轻量模式。
- 只使用 Draft / Accepted 作为阶段审查状态；当前为 T01/T03/T04 Verification Accepted、T02-T05 Intent/Plan Accepted，T06-T09 Intent 为 Draft。
- 采用现有 Playwright 能力处理浏览器等待、DOM 定位和请求；不自建通用 JS/Python 表达式引擎。
- 嵌套校验、参数解析时机和重试边界归入相关基础任务，不另立无关的全项目重构任务。
- 用户明确“不做兼容适配”。各任务以新契约正确性为目标；必要的旧接口移除和仓库内调用迁移纳入对应任务，外部调用方迁移另行处理。

## Risks

- 运行时数据影响顶层、嵌套、重试和数据驱动执行，错误的作用域或解析时机会影响所有新流程；旧调用方需要迁移，不能通过适配层掩盖接口变化。
- 不同条件运行在执行器或浏览器中，必须明确数据可见范围，不能继续依赖隐含的页面全局状态。
- 请求复用 Cookie 不等于自动复制 localStorage 中的认证信息；调用方仍需明确必要的请求头。
- 本地示例能验证组合能力，不能证明外部生产页面在数据并发变化或认证过期时的行为。
