## Background

仅对新增步骤分别做测试，无法证明类型引用、作用域、页面导航、顺序遍历和轮询可以协同工作。material-parse-all 的复杂度提供了现实参照，但它依赖外部项目、认证和真实解析服务，不宜作为本工具日常验证的必需条件。

## Goals

- 在当前仓库提供一个受控、可重复的复杂流程示例，串联全部 P0/P1 能力。
- 验证分页列表、状态分支、顺序提交、异步终态与最终汇总的组合行为。
- 更新用户及 Agent 说明，让调用方能发现和使用新能力。

## Non-goals

- 不修改或运行相邻 K12 项目的 material-parse-all，不要求真实 Casdoor 或 MinerU 服务。
- 不制作生产业务页面或增加专用业务步骤。
- 不以单纯缩短 YAML 或把 JS 挪入文件作为验收依据。

## User scenarios

- 开发者运行受控示例，复现多页记录、已完成、缺少文件、格式不支持、已有任务、新任务成功和新任务失败。
- Agent 参考说明，用通用步骤编写同类流程，而不再手写页面存储状态机和轮询函数。

## Acceptance

- 示例直接使用 T01-T08 的公开契约，能稳定复现正常、跳过、业务失败、读取失败和超时场景。
- 页面就绪与数据提取配合，多页记录既不遗漏也不重复；当前任务结束后才提交下一项。
- 没有 sessionStorage 循环状态机、手写 delay/waitFor 或重复 fetch/JSON 错误处理；特殊转换若需短 JS，要明确用途。
- 运行输出能够核对处理总数、逐条分类与错误原因，业务失败政策通过显式断言表达。
- 验证作用域隔离、迭代失败定位、不会隐式重放已提交操作，以及 --json 和退出码的组合行为。
- 使用受控页面和模拟接口，常规验证不依赖外部业务系统；测试环境形态在 Plan 中确定。
- README、示例说明、步骤规范及内置 Agent skill 的新增能力说明保持一致。
- 确认仓库示例、测试和说明统一使用新契约，不残留旧格式适配；记录尚需外部调用方迁移及验证的页面和认证差异。

## Open questions

本系列交付仓库内受控示例，真实 K12 flow 迁移不在本任务内。采用独立回环 HTTP fixture 与会话隔离的模拟接口；暂无必须由用户决定后才能继续的未决事项，实施范围见 Plan。

## Decisions

- 此任务是系列集成验收，不代替 T01-T08 各自的验证。
- 不启动或复用外部项目开发服务器，不向实际解析服务提交任务。
- 通过步骤组合完成普通分页，不提前实现 P2 的专用分页能力。
- 不维护新旧两套示例；按用户要求完成仓库内新契约迁移的集成核对。

## Risks

受控示例只能验证公开契约和常见交互时序，不能证明外部页面全部选择器、认证和并发更新行为。若发现通用能力缺口，先更新相关任务意图与计划，再决定补齐范围。
