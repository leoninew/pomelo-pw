## Background

StepResult 已能携带数据，但后续步骤无法引用保存的结果。变量替换将引用值转成字符串，字段路径、原生集合和运行时作用域缺少契约。业务 flow 因而借用 sessionStorage 保存记录及进度。

## Goals

- 为一次 flow 执行提供结果保存和引用机制，成功步骤可将明确的输出绑定为命名数据。
- 支持对象、数组及标量的类型化传递和字段访问，统一完整引用与文本拼接的类型语义。
- 为分支、循环、轮询和 data-driven 执行明确运行时数据的共享与隔离边界。
- evaluate 能通过结构化参数接收数据，减少把对象和字符串拼接进 JS 源码的需要。

## Non-goals

- 不增加条件、集合迭代、HTTP 请求或 DOM 提取步骤，这些由后续任务实现。
- 不实现跨进程持久化、恢复、任意表达式求值或通用数据转换语言。
- 不进行与数据上下文无关的执行器重构。
- 不维护旧字符串替换语义、双份结果字段、模块脚本适配或旧调用路径的兼容分支。

## User scenarios

- evaluate 返回记录数组，后续步骤以原生数组消费；接口返回对象，后续参数引用其 ID 或状态。
- 同一个结果在顶层及嵌套分支中可见，步骤局部变量不会泄漏到其他步骤。
- evaluate 接收含引号、换行的字段或对象，无需调用方手动转义为 JS 源码。

## Acceptance

- 保存和引用 null、布尔、数值、字符串、对象及数组，能访问嵌套字段，并给出明确的缺失引用错误。
- 完整引用统一保留原生类型，文本拼接统一生成字符串；规则不因输入来源或旧写法不同而分叉。
- 成功结果能被后续步骤读取；失败或未执行步骤不生成新的成功绑定，旧值是否保留必须有明确约定。
- 顶层与嵌套步骤使用一致的结果写入规则，局部覆盖及运行输入的优先级有明确约定。
- data-driven 的不同行之间隔离运行结果，避免上一行数据被下一行误用。
- 嵌套参数在实际执行到该步骤时解析，允许引用同一分支中前一步才产生的数据。
- evaluate 使用带结构化参数的函数脚本，通过 Playwright 参数传递对象和特殊字符；旧模块脚本由调用方改写为函数，不提供适配路径。
- 嵌套结果绑定参数可被 validate 检查，错误能定位到具体步骤路径。

## Open questions

暂无必须由用户决定的未决事项。结果命名空间、绑定字段、类型化引用语法、字段路径范围和局部作用域的精确规则在 Plan 阶段形成可审查方案。

## Decisions

- 结果传递是其他任务的前置契约，优先完成并验收。
- 公开输出与控制步骤的内部调度数据使用明确分离的契约，不为旧结果访问方式重复写入输出。
- 不允许结果绑定隐式改变 CLI 与 flow 输入的覆盖约定；现有文档和代码的优先级差异在 Plan 中显式处理。
- 用户已明确不做兼容适配；按新契约设计并迁移仓库内相关测试、示例和说明。

## Risks

完整变量引用保留原生类型可能影响 fill、URL、selector 和输出路径。作用域、延迟解析、重试及数据驱动隔离需要一起核对，不能只给 evaluate 增加保存字段。
