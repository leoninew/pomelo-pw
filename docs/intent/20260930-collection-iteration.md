## Background

当前 foreach 是 loop 的别名，仍需提供 times 或 while。业务 flow 为遍历运行时记录数组，手动维护 index、current 和退出条件，增加了状态机代码。

## Goals

- 遍历运行时得到的集合，按顺序执行每条记录的步骤。
- 在迭代内提供当前元素和索引，支持字段引用及基于数据的分支。
- 明确嵌套循环的局部作用域、空集合和失败行为。

## Non-goals

- 不增加并发遍历、流式无限集合或跨运行恢复。
- 第一版不引入 break/continue 等跳转控制；跳过某项可通过条件分支表达。
- 不改变既有 data-driven 模式每行独立运行的用途。

## User scenarios

- 遍历提取到的记录数组，对每项读取状态、提交或跳过，并等待当前任务结束再进入下一项。
- 遍历多页数据中的行集合，内外循环分别引用自己的当前项。

## Acceptance

- 原生数组可作为遍历输入；按原始顺序执行，空数组执行零次，非法输入给出明确错误。
- 当前元素及索引可在选择器、URL、请求体、条件和 evaluate 参数中引用。
- 嵌套循环的局部元素不相互覆盖，退出迭代后不泄漏局部绑定。
- 遍历开始后的输入集合采用明确且稳定的快照或变更规则，不能因回写结果发生隐式重遍历。
- 失败能定位到迭代索引和嵌套步骤，默认不重放此前成功的迭代或已完成的写操作。
- 次数循环、条件循环与集合遍历各有明确契约和互斥参数，可递归校验；foreach 不再适配原先作为 loop 别名的参数组合。

## Risks

当前重试包装覆盖嵌套控制步骤，失败时可能重放整个循环。扩展集合遍历时必须明确重试边界，避免重复提交；这是本任务的相关行为修正。
