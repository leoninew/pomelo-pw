## Background

现有条件支持页面检查及 JS 表达式，但无法直接比较执行器保存的结构化数据。通过字符串是否包含冒号判断条件类型，也会误判包含冒号的 JS。if、while 及未来等待和断言需要共享可预测的条件契约。

## Goals

- 支持运行时数据的比较、存在性和集合成员判断，以及 all/any/not 组合。
- 明确页面条件、数据条件和 JS 谓词各自的数据来源及执行位置。
- 让 if、while 及后续等待、轮询和断言复用同一条件语义。

## Non-goals

- 不开发任意算术、映射或过滤表达式语言，不执行 Python eval。
- 不新增集合迭代、等待时序或请求能力。
- 不修正控制体整体重试、循环耗尽及执行报告，这些继续由 T03、T05、T08 处理。

## User scenarios

- 根据记录是否有文件、解析状态是否 ready，决定处理分支。
- 判断任务状态是否属于终态集合，或 URL 和目标元素是否同时满足要求。

## Acceptance

- 能比较引用数据及常量，明确相等、不相等、存在性和集合包含的类型语义。
- all/any/not 可组合，空组合、缺失字段、null 和 false 有明确行为。
- 顶层和嵌套的 if、while 使用相同规则；结果变化后条件读取最新值。
- 页面谓词与运行时数据通过明确参数连接，不要求把状态写入 window 或 sessionStorage。
- 页面检查、数据判断与 JS 谓词使用明确的新条件结构，不提供旧冒号条件字符串的识别和适配分支。
- validate 能检查嵌套条件结构和不支持的操作符，并定位错误步骤。

## Open questions

暂无必须由用户决定的未决事项。条件 YAML 的精确结构、短路行为及比较操作符在 [Plan](../plan/20260930-structured-flow-conditions.md) 中明确，第一版只覆盖上述通用判断。

## Decisions

- 公共条件契约供控制步骤及后续任务复用，避免每个新增步骤独立实现判断语法。
- 保留页面 JS 谓词作为扩展方式，不把 JS 对象内省或复杂表达式解析纳入核心语法。
- 遵循用户指定的新契约政策，不兼容旧条件语法；仓库内条件示例和测试随本任务迁移。

## Risks

不同执行位置的条件若隐式读取不同数据，会再次迫使调用方使用页面存储。旧冒号条件和隐式 JS 条件必须迁移为明确的新结构，不能通过猜测字符串类型适配。
